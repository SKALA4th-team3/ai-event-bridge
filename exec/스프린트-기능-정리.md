# 이벤트브릿지 — 스프린트별 기능 정리

공공 이벤트 발주 매칭 플랫폼. 발주 기관이 이벤트 공사를 공고하면, 참여 업체가 지원하고 기관이 선정합니다.

**구분 표기**

| 표기 | 뜻 |
|---|---|
| **B** | 참여 업체 (Business) |
| **G** | 발주 기관 (Government) |
| **C** | 공통 — 양쪽이 함께 쓰는 기능 |

> 이 서비스는 업체 ↔ 기관 매칭이라 일반 소비자(Consumer)가 없습니다.
> `C`는 소비자가 아니라 **공통(Common)** 기능을 가리킵니다.

`HTTP Method` 칸의 `—`는 **백엔드 호출이 없는 프론트엔드 전용 기능**입니다.

## 백엔드를 고치지 않고 도메인을 옮긴 방법

실습 템플릿의 `courses` 테이블은 평면 구조라 **계층 · 마감일 · 자격요건**을 담을 자리가 없습니다.
`description` 컬럼에 섹션 규약을 정해 그 안에 실었습니다.

```
[이벤트] 진해 군항제
[기간] 2027-03-28 ~ 2027-04-06
[마감] 2027-01-27
[지역] 경남 창원
[기관] 경남 창원시청
[과업] 중원로터리 일대 안전요원 일 50명 배치, 인파 밀집 구간 동선 관리.
[자격요건]
업종: 경비·안전관리업
업력: 3년 이상
```

**Anti-Corruption Layer**(`api/posting.js`)가 이 규약을 파싱해 백엔드의 `course` · `enrollment`를
우리 도메인의 `공고` · `지원`으로 옮깁니다. 화면은 백엔드 스키마를 모릅니다.

| 백엔드 | 우리 도메인 |
|---|---|
| `course` | 공고 |
| `enrollment` | 지원 |
| `title` | 공사명 |
| `price` | 사업 예산 |
| `category` | 공사 분야 |

이 구조 덕분에 백엔드가 확장되면 **ACL 파일만 고치면** 화면 전체가 따라옵니다.

## AI를 쓴 방식

화면에서 “AI”라고 부르는 곳이 네 군데인데, **실제 언어모델은 검색 하나뿐**입니다.

| 화면 | 구현 | 정체 |
|---|---|---|
| AI 1순위 · AI 검토 의견 | `demoBidders.js` `reviewOf()` | 규칙 기반 |
| 적합도 % | `useFitScore.js` `fitScore()` | 규칙 기반 |
| 우리 업체에 맞는 공고 | `useFitScore.js` `recommendFor()` | 규칙 기반 |
| **문장 검색** | `lib/aiSearch.js` → Gemini | **언어모델** |

### 적합도 산식 (규칙 기반)

| 항목 | 배점 | 만점 기준 |
|---|---|---|
| 업종 일치 | 45 | 공고 분야 == 업체 업종 |
| 지역 해당 | 20 | 업체 활동 권역에 공고 지역이 있으면 |
| 수행 실적 | 20 | 요건의 **2배**를 채우면 (비례 배분) |
| 업력 | 15 | 요건의 **1.5배**를 채우면 (비례 배분) |

실적 · 업력을 절대량이 아니라 **“그 공고가 요구하는 수준 대비”** 로 잽니다.
절대량으로 재면 요건을 넉넉히 넘는 업체가 모든 공고에서 같은 점수를 받아 정렬이 무의미해집니다.

### AI 검색 — 결과가 아니라 조건을 만들게 합니다

```
"다음 달쯤 남부지방에서 무대 쪽 일감 있나"
        ↓  Firebase AI Logic → Gemini
{ period: "다음 달",
  regions: ["전라", "경상", "제주"],
  categories: ["무대·음향"] }
        ↓  applyFilters
   기존 공고 데이터에서 걸러 낸 결과
```

설계 판단 두 가지입니다.

1. **AI에게 검색 결과를 만들게 하지 않습니다.** 결과는 이미 받아 둔 목록에서 고르므로
   환각으로 존재하지 않는 공고가 나올 수 없습니다. AI가 실패해도 규칙 파서가 받아 검색은 계속됩니다.
2. **AI가 고를 수 있는 값을 스키마 `enum`으로 우리 필터 라벨에 묶었습니다.**
   자유 키워드를 받으면 `부스설치`처럼 한 글자 다른 값이 와서 조용히 0건이 됩니다.

**Firebase를 거치는 이유** — Gemini를 직접 부르면 API 키가 브라우저 번들에 들어갑니다.
Firebase AI Logic이 프록시가 되어 키는 내려오지 않고, “우리 앱에서 온 요청인가”를
App Check(reCAPTCHA v3)가 증명합니다.

## 스프린트 3 백로그

스프린트 2에서 **백엔드를 고치지 않아** 프론트엔드로 대신한 것들입니다.
아래가 생기면 해당 화면이 실데이터로 바뀝니다.

| 필요한 것 | 지금 상태 | 열리는 기능 |
|---|---|---|
| `EnrollmentRepository.findByCourseId` | 공고별 지원 업체 조회 API 없음 | 선정 모달이 시연 데이터 → 실데이터 |
| `enrollments.bid_amount` 컬럼 | 제안 금액이 저장되지 않음 | 금액 비교 · 예산 대비 분석 |
| 제안서 파일 저장소 | 업로드만 하고 버림 | 서류 심사 |
| 목록 API 검색 · 필터 파라미터 | 전체를 받아 클라이언트에서 거름 | 데이터가 늘어도 견딤 |
| 관심 공고 저장 API | `localStorage` | 기기 간 동기화 |
| `PATCH /api/users/me` | 내 정보 수정이 화면에만 반영 | 프로필 영속화 |
| 선정 확정 API | 화면 상태로만 관리 | 선정 결과 통보 |

`ai-knowledge` 모듈에 `GET /api/events/{id}/performance` · `POST /api/events/{id}/bids`가 있으나
“AI 활용 데이터 자산 현황” 화면은 아직 시연 데이터를 씁니다. 연결이 남아 있습니다.
