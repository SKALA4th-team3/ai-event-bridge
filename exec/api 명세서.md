## 1. Auth

| 코드 | 기능명 | 설명 |
| --- | --- | --- |
| `POST /api/users/signup` | 회원가입 | 이메일, 비밀번호, 이름, 역할을 입력하여 가입한다. 역할에 따라 기관 또는 업체 추가 정보를 입력한다.
(기관 담당자일 경우 기관 도메인 이메일인 `@*.go.kr`로 인증) |
| `POST /api/users/login` | 로그인 | 이메일과 비밀번호가 일치하면 액세스 토큰과 리프레시 토큰을 발급한다. |
| `POST /api/users/logout` | 로그아웃 | 저장된 리프레시 토큰을 삭제한다. |
| `GET /api/users/verify` | 토큰 확인 | 액세스 토큰이 유효한지 확인하고 사용자 ID와 역할을 반환한다. |
| `POST /api/users/refresh` | 액세스 토큰 갱신 | 리프레시 토큰이 서버 저장값과 일치하면 새로운 액세스 토큰을 발급한다. |

### 회원가입 입력 정보

| 역할 | 입력 정보 |
| --- | --- |
| 공통 필수 | 이메일, 비밀번호, 이름, 역할, 연락처 |
| `ADMIN` | 기관명, 부서·담당자, 담당 분야, 연간 발주 규모 |
| `COMPANY` | 상호명, 사업자등록번호, 업종, 서비스 가능 지역 |

## 3. Event

> API 경로의 `events`는 축제 자체가 아니라 **축제 사업 입찰공고**를 의미한다.
> 

| 코드 | 기능명 | 설명 |
| --- | --- | --- |
| `POST /api/courses` | 공고 등록 | `ADMIN`만 가능하다. 최초 상태는 `DRAFT`다. 

~[1] 기본 정보 소속 이벤트, 공사 분야, 공사명, 사업 예산(원), 지원마감일수
[2] 과업 내용, 자격 요건 ← 화면 설계에서 [1]로 선택되어 있는 문제 수정 필요~ |
| `GET /api/courses` | 공개 공고 목록 | `PUBLISHED`, `OPEN` 상태의 입찰공고를 지역, 분야, 예산, 기간으로 조회한다. |
| `GET /api/courses/{eventId}` | 공고 상세 | 공개된 공고의 사업 조건, 예산, 기간, 필요 인력, 입찰 기간을 조회한다. 

공고 개요) 발주 기관, 사업 기간, 사업 예산, 지원 마감, 계약 방식, 공사 분야 / 과업 내용 / 자격요건 대조 |
| `PATCH /api/courses/{eventId}` | 공고 수정 | 등록한 `ADMIN`만 가능하며 `DRAFT` 상태에서만 수정할 수 있다.  |
| `DELETE /api/courses/{eventId}` | 공고 삭제 | 등록한 `ADMIN`만 가능하며 `DRAFT` 상태이고 입찰이 없을 때만 가능하다.  |
| `POST /api/courses/{eventId}/open` | 공고 접수 시작 | `DRAFT` 상태를 `PUBLISHED`로 변경한다. 업체는 공고를 조회할 수 있지만 아직 입찰 지원은 할 수 없다.  |
| `POST /api/courses/{eventId}/publish` | 공고 공개 | `PUBLISHED` 상태를 `OPEN`으로 변경한다. 업체가 입찰 지원할 수 있다.  |
| `POST /api/courses/{eventId}/close` | 공고 마감 | `OPEN` 상태를 `CLOSED`로 변경하고, 제출된 입찰을 `UNDER_REVIEW`로 변경한다.
~더이상 입찰 지원을 할 수 없다.~ |
| `GET /api/courses/enrollments` | 공고 목록 조회 | `ADMIN` 이 자신이 등록한 공고에 입찰 신청한 업체와 지원 내용을 조회한다.
내 공고 - 상태 상관없음. 공고명, 예산, 지원 수, 마감 디데이, 상태
처리 대기 - 마감된 공고만(CLOSED) 리스트 업.
아이템 눌렀을 때 해당 공고에 신청한 업체 목록 하단에 카드로 보여주기
(공고 + 신청 업체 정보 한 번에 가져오기)
(카드 : 업체명, 업종, 서비스 가능 지역, 가라-제출 파일에서 LLM이 요약 정리, 적합도)

### 이벤트 상태

> 복잡도 감소를 위해 DRAFT 제거
> 

> 공고 기간 전 미리 이벤트를 등록하는 경우를 위해 `PUBLISHED` 상태 유지 유무 고려 필요
> 

| 상태 | 업체 노출 | 입찰 지원 | 의미 |
| --- | --- | --- | --- |
| `PUBLISHED` | O | X | 업체에 공개되었지만 입찰 접수 전 |
| `OPEN` | O | O | 입찰 접수 기간이며 업체가 입찰 지원 가능 |
| `CLOSED` | O | X | 입찰 마감 후 심사 진행 중 |
| `AWARDED` | O | X | 낙찰 업체 선정 완료 |
| `COMPLETED` | O | X | 사업 종료 |
| `CANCELLED` | 정책에 따라 | X | 사업 취소 |

## 4. Apply

| 코드 | 기능명 | 설명 |
| --- | --- | --- |
| `POST /api/courses/{eventId}/enrollments` | 지원 | `COMPANY`만 가능하다. `OPEN` 상태 공고에 입찰 금액과 사업계획을 제출한다. 최초 상태는 `SUBMITTED`다. |
| `GET /api/enrollments/{applyId}` | 지원 상세 조회 | 지원 업체와 공고 등록 관리자만 조회할 수 있다.
 |
| `PATCH /api/enrollments/{applyId}` | 지원 수정 | 신청한 `COMPANY`만 가능하다. 입찰 마감 전, `SUBMITTED` 상태에서만 수정할 수 있다. 제출 서류를 재업로드한다. |
| `DELETE /api/enrollments/{applyid}` | 지원 취소 | 신청한 `COMPANY`만 가능하다. 입찰 마감 전 상태를 `WITHDRAWN`으로 변경한다. |

### 입찰 규칙

- 업체는 하나의 공고에 한 번만 지원할 수 있다.
- `WITHDRAWN` 입찰은 낙찰 대상에서 제외한다.
- 입찰 금액은 `Apply`에 저장하며, 정수 또는 `DECIMAL` 타입으로 관리한다.
- 제안서 파일은 MVP에서 파일 URL 또는 저장 키만 저장한다.

### 입찰 상태

상태 정보를 화면 정보와 통일? (11_내지원관리)

| 상태 | 의미 |
| --- | --- |
| `SUBMITTED` | 입찰 지원 완료 |
| `UNDER_REVIEW` | 심사 중 |
| `AWARDED` | 낙찰 |
| `NOT_AWARDED` | 미낙찰 |
| `WITHDRAWN` | 입찰 취소 |

## 5. Award

| 코드 | 기능명 | 설명 |
| --- | --- | --- |
| `POST /api/courses/{eventId}/payments` | 낙찰 업체 선정 | 공고 등록 `ADMIN`만 가능하다. `CLOSED` 상태 공고의 심사 중 입찰 하나를 낙찰 처리한다.
공고 등록 `ADMIN`이 낙찰 이후 사업 상태를 `COMPLETED`로 변경한다. |
| `GET /api/courses/{eventId}/payments` | 낙찰 결과 조회 | 공고 관리자와 참여 업체가 낙찰 결과를 조회한다.

| `POST /api/courses/{eventId}/complete` | 사업 종료 | 공고 등록 `ADMIN`이 낙찰 이후 사업 상태를 `COMPLETED`로 변경한다. |

### 낙찰 요청 예시

```
{
  "applyId": 15,
  "awardReason": "사업 수행 역량 및 제안 금액 종합 평가 결과"
}
```

### 낙찰 처리 규칙

```
조건:
- 이벤트 상태: CLOSED
- 선택 입찰 상태: UNDER_REVIEW

처리:
- 선택 입찰: AWARDED
- 나머지 심사 중 입찰: NOT_AWARDED
- 이벤트 상태: AWARDED
- 낙찰 금액: 선택 입찰의 applyAmount를 지급 예정 금액으로 기록
```

## 6. Recommend

| 코드 | 기능명 | 설명 |
| --- | --- | --- |
| `GET /api/recommend/courses` | 추천 공고 조회 | 업체의 업종, 보유 인력, 이전 입찰 분야를 기준으로 참여 가능성이 높은 `OPEN` 공고를 반환한다.
카테고리 상단 - 추천 업체 |

### 추천 규칙

1. 업체의 업종과 공고 행사 분야가 일치하는 공고를 우선 조회한다.
2. 업체 보유 인력과 공고 필요 인력을 비교한다.
3. 이미 지원했거나 마감된 공고는 제외한다.
4. 입찰 마감일이 가까운 순으로 최대 5건을 반환한다.
